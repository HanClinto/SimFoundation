# Atomic Group Landing Areas

Campaign admission should not place multiple blocking people on the same tile
when local movement explicitly prevents that overlap. Transfers now accept an
optional small arrival radius. The primary pad must remain clear, and each
blocking ground root receives a distinct currently free floor tile in stable
ID order; candidate order is distance, row, then column. Nonblocking roots
can share the pad under ordinary occupancy rules.

The whole travelling group waits if it cannot fit. No partial admission, new
entity, map-wide relocation or lost passenger is introduced. Nested ownership
remains unchanged. Restraint breakage during transit can create new loose roots,
which are included in the same current-state landing calculation. Physiology
and custody still advance once, and admitted records receive no extra turn.

Generic callers without an arrival area retain the explicit point-arrival
contract. Campaign/reserve operations request radius1. A radius0 request can
instead require a genuinely single blocking root; radii are bounded to3.
This is not a traffic planner or save migration. Core35 discards incompatible
development transfers. Group, insufficient-space, default-contract and saved
replay tests accompany complete peaceful/danger/care/evacuation walkthroughs.
